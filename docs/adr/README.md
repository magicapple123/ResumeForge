## 什么时候要写 ADR

- 决策会影响**多个模块**、以后可能被问"为什么这么做"；
- 有两个以上看起来都合理的方案，且选择理由是**约束**而不是偏好；
- 决策**推翻了已有实现**（必须同时更新被推翻的那份 ADR）。

## 写作要求

1. 标题一句话说清决策，不写"关于……的思考"。
2. 正文必须有：背景 / 决策 / 后果（含代价）/ 替代方案。
3. 引用的常量与路径写**当前值**，历史值标「1.x 历史号」或「后续修订」。
4. 被推翻时改状态并加「后续修订」小节，**不要删原文**——决策的上下文比结论更值钱。
