# 缺陷模式速查

> 用法：提 bug、写验收、做 code review 时按"判据"一列对照。命中某条模式，直接跳到"守卫"一列看该补什么。
> 这些模式来自多个项目的真实缺陷归纳，**以 Web 全栈为主**（前后端 + 渲染/导出）；示例一律抽象化。跨栈使用时按"判据"迁移，不要照搬实现。

## 0. 三条元规则

1. **能被一条断言描述的才是模式，其余是个案。** 写不出判据的缺陷，先别急着归类。
2. **每个模式都要有"为什么容易漏"。** 不写这一列，团队会反复踩同一个。
3. **守卫优先于文档。** 写进规范的约束会被遗忘，写成可执行检查的不会。

## A. 契约与数据流

### A1 契约能力缺口

**判据**：界面承诺的动作，在某个档位（旧数据、某个模板、某个导出格式、某个权限）下必然失败。
**为何易漏**：失败路径是"合法报错"，看起来不是 bug；真正的 bug 是入口不该存在。
**守卫**：做一张"功能 × 前置条件"能力矩阵，不满足即禁用并写明原因，而不是让用户点了才知道。

### A2 读接口 DTO 整份回传写端点

**判据**：GET 返回的对象被原样塞进 POST/PUT；写端点开了"拒绝多余字段"。
**为何易漏**：类型检查不做对象字面量的多余属性检查，变量赋值合法；只有运行时才 422。
**守卫**：读写两侧各有一个显式投影函数；新增字段必须同时回答"是否可写"。

### A3 跨层允许集漂移

**判据**：前后端各有一份"哪些值合法"的列表，没有对拍。
**为何易漏**：单侧自测全绿；不一致时表现为"下拉框里出现英文枚举"或"某选项永远选不中"。
**守卫**：双向 parity 测试（前端允许集 == 后端消费集），并在选项列表对当前值做兜底显示。

### A4 双生产者 / 单消费者

**判据**：一个集合由两处 append，两处对同一字段的语义不同，消费方却按"每键唯一"建索引。
**为何易漏**：类型完全相同；只有运行时才出现重复 key 或顺序错乱。
**守卫**：数据结构上带粒度标记；渲染前按归一键聚合，并加"聚合前后总数不变"的不变量测试。

### A5 无去路字段

**判据**：某字段既不在白名单槽位、又被禁止写入正文、也不在覆盖度清单里。
**为何易漏**：三条路各自都是"正确设计"，合起来才成为缺陷；用户只感到"我填了但没出现"。
**守卫**：建一张"字段 × 出口"可达性矩阵，每个字段至少一个出口，或被显式标为"仅素材"。

### A6 可见性判据旁路

**判据**：`hidden/private` 只在统一消费层生效，而某个出口（搜索、导出、统计）直接读存储层原始数据。
**为何易漏**：旁路代码看起来只是"一个简单的查询"，评审时不会联想到权限。
**守卫**：可见性判据只允许一份实现并提升为公共入口；对"绕过唯一入口"的函数做调用点白名单。

### A7 归一化口径不一致

**判据**：比较双方对同一文本做了不同程度的清洗（一侧保留 `- ` 前缀、一侧已剥）。
**为何易漏**：`strip()` 看起来已经"清洗过了"，但 `-` 不是空白字符；一旦资料用列表写就 100% 复现。
**守卫**：归一化函数唯一化 + 双向 fixture（带前缀 vs 已剥离），并保留"含连字符的正常文本不被误剥"的反向断言。

### A8 检查在清洗之前

**判据**：一致性检查读的是原始输出，随后的清洗又删掉不合格项，于是警告指向一个已不存在的东西。
**为何易漏**：两个模块单测都通过；缺陷只在"警告 + 产物"联合看时才显形。
**守卫**：检查与清洗共用同一份事实集合，或强制"清洗产出 removed 清单 → 警告由 removed 生成"。

### A9 缓存缺身份/版本/过期表达

**判据**：缓存键不含实体 id、内容版本或数据域；键变了直接拒绝读取。
**为何易漏**：单数据集、单文件时永远正确。
**守卫**：键 = 实体 + 内容签名 + 域；"过期"用显式状态表达，而不是把结果丢掉。

### A10 引用相等当内容相等

**判据**：用 `===`、对象引用、DOM 引用判断"是否变化/是否过期"。
**为何易漏**：不可变更新下"通常成立"，一旦宿主换了新对象就整条链路失效。
**守卫**：用版本号/内容哈希代替引用；给"必须返回新引用"写进约定。

## B. 状态与时序

### B1 状态机缺复位边

**判据**：有 `suspend` 没有对称的 `resume`；有"只执行一次"的副作用没有重放路径。
**为何易漏**：进入路径被频繁走到，退出路径只在特定操作序列下暴露。
**守卫**：画状态迁移表，每个挂起必须有对称恢复 + 有界重试/超时。

### B2 中间态缺失

**判据**：两个应独立的阶段被一个函数一次做完，导致"想走分支 B"必须先完成阶段 A。
**为何易漏**：端到端主流程是通的，缺陷只在新增分支时才暴露成 409/422。
**守卫**：拆成两个显式状态 + 幂等端点，并补"刷新后恢复到中间态"的用例。

### B3 赋值顺序竞态

**判据**：`running=false` 与 `thread=null` 的写入顺序反了；取消时先写终态再等线程退出。
**为何易漏**：单线程测试永远绿；只有并发窗口命中。
**守卫**：消除写入顺序（先 join 再写终态），而不是把等待时间调大；测试等两态都落定。

### B4 TOCTOU

**判据**：两个执行体并发读同一全局量再各自写回。
**为何易漏**：低频操作，压测才出；日志里表现为"数字偶尔多记一次"。
**守卫**：读改写加锁或用原子操作；用"总数守恒"断言兜底。

### B5 只测终态不测中断

**判据**：取消/超时/断网分支没有用例，或复用了同一个事件对象导致取消只生效一次。
**为何易漏**：正常路径覆盖率高，容易误以为"状态机都测了"。
**守卫**：每个可取消操作补"取消中 / 取消后重试 / 已有部分结果"三类用例。

## C. 呈现与布局

### C1 幽灵类名

**判据**：`class` 出现在组件里，全项目样式表零命中。
**为何易漏**：不报错、单测全绿（断言文本与行为，不断言样式）；唯一症状是"看起来没排过版"。
**守卫**：扫描组件里的静态类名 token，只守自有前缀；白名单带理由与到期日，并检查"幽灵豁免"（豁免对象已不存在）。

### C2 布局假设写死

**判据**：样式里出现 `right: 0`、"左 50% + translateX(-50%)"这类假定锚点在固定角的写法，而锚点可被拖动或换位。
**为何易漏**：默认位置永远正确，只有用户把元素拖到另一边才暴露。
**守卫**：坐标夹取抽成纯函数并单测组合（锚点位置 × 元素尺寸 × 视口），样式只管静态外观。

### C3 可收缩项被压到 0

**判据**：一行里唯一可收缩的项被设成 `flex: 1 1 auto; min-width: 0`。
**为何易漏**：宽屏正常，窄屏时它被压到 0 宽、内容溢出，后绘制的元素盖住前一个。
**守卫**：判据落在 `scrollWidth == clientWidth` 与各元素 `rect` 上，而不是读 CSS 猜。

### C4 硬编码数值叠加

**判据**：多层吸顶/偏移靠"上一层的实测高度"累加。
**为何易漏**：改任意一层高度，其它层不跟着变；症状是"半截被裁的行"。
**守卫**：用 flex/grid 分层，不靠数值累加；文档里禁止引入第二个 magic number。

### C5 静态样式压不过运行时注入

**判据**：覆盖第三方组件库的外观时，类名挂载点正确、规则也活着，但样式不生效。
**为何易漏**：运行时注入的样式排在静态表之后，同特异性必胜；`margin` 还会与相邻元素塌陷。
**守卫**：间距类改动走内联样式或设计令牌；覆盖前先用 `getComputedStyle` 实测，不靠读源码下结论。
（C6 是同一根因的另一形态：内联样式压过样式表；两条一起看，判据可以合并成"谁在最后、谁更具体"。）

### C6 内联样式优先级

**判据**：目标元素上已有内联 `style`，却又新写了类规则。
**为何易漏**：新规则永远不生效，而且"看起来改了"（代码里确实有）。
**守卫**：改外观前先把内联样式搬进样式表，再改类规则。

### C7 多出口不一致

**判据**：同一份数据有 3 个以上渲染器（页面 / HTML / PDF / Word / Markdown），各自实现换行、间距、边框、分页。
**为何易漏**：每个渲染器单测都过，缺陷只在"同一份内容导多种格式"时出现。
**守卫**：跨格式 parity 测试（同内容 + 同参数 → 各格式正文一致）；无法根除的差异写进交付说明。

## D. 静默失败

### D1 静默丢弃 / 静默成功

**判据**：`if x is None: continue`、返回空结果却回 200、开关关闭时照样收下指令。
**为何易漏**：这是最"干净"的实现路径，代码可读性反而更好；用户侧只表现为"没反应"。
**守卫**：任何丢弃都要产出可展示的 skipped/removed 清单；"无操作"必须是显式状态而非成功码。

### D2 空态同义合并

**判据**：三种不同成因（没填 / 被过滤 / 字段名不匹配）共用一句"没有匹配项"。
**为何易漏**：根因通常在数据层把"不存在"与"被裁掉"压成了同一个结构。
**守卫**：空态携带 `reason` 枚举，差异清单在数据层就补出来，不让前端猜。

### D3 单位/时区/精度口径缺失

**判据**：时间少 `Z`；百分比分母是"当前最大值"而非总量；换算常量散落在注释里且注释本身是错的。
**为何易漏**：单点看都"差不多"，只在并排对比或跨端时暴露。
**守卫**：单一换算模块 + 展示口径写进类型；测试固定换算常量，时间断言显式传时区。

### D4 累积阶梯被整体否决

**判据**：候选是累积覆盖的（第 N 档包含前 N−1 档的改动），过滤却按"最终值"判定。
**为何易漏**：过滤函数本身逻辑正确，错在它拿到的是累积结果而非增量。
**守卫**：按"新引入的改动"判定，或把阶梯截断在阈值处。

### D5 提示词模板无条件列举可选项

**判据**：JSON 输出模板写死全部字段，未启用的部分也照样出现。
**为何易漏**：看起来是模型幻觉，实际是模板在要求它幻觉。
**守卫**：模板按候选数据条件渲染；验收直接断言"渲染后的提示词不含未启用项"，不必真跑模型。

## E. 测试与工程约束

### E1 测试把缺陷固化成契约

**判据**：断言写的是现状而非意图，例如"以某个错误符号开头"。
**为何易漏**：这类测试全绿，改 bug 时它们第一个变红，容易被理解成"改坏了"。
**守卫**：修 bug 前先问"这条断言描述的是意图还是现状"；新测试必须能对旧实现失败。

### E2 测试补齐生产缺失的依赖

**判据**：为了让用例跑通，在测试里给每个渲染点包上生产环境并不存在的 Provider/上下文。
**为何易漏**：测试绿了，生产白屏；而且"补依赖"看起来是良好实践。
**守卫**：测试环境不得补生产缺失的依赖；补一条"没有包裹也必须能渲染"的用例。

### E3 守卫只锚结构不校验内容

**判据**：守卫只检查"条目存在/数量相等"，不检查条目里的文字或数值。
**为何易漏**：文件齐全、数量正确，内容早已与事实相反。
**守卫**：每条守卫至少一条内容断言，且证明"解析到 0 项必须失败"，否则正则失效会恒绿。

### E4 机械约束与格式化工具冲突

**判据**：文件行数卡在预算线上，而格式化工具会重排。
**为何易漏**：新增文件"刚好 500 行"，格式化后 624 行，CI 才红。
**守卫**：新增文件先格式化再数行；贴线等于"下次改动必须先拆"，应在评审时就要求拆。

## 使用建议

| 场景 | 怎么用 |
|---|---|
| 提 issue | 对照 A–E 找模式，在标题里带上模式名（如 `[A2] 读 DTO 回传写端点导致 422`），便于聚合 |
| 写验收 | 每条验收至少覆盖一个"该模式的守卫"，否则这条缺陷很可能再犯 |
| Code review | 先扫 C/D 两类（最容易在评审中被当成"风格问题"放过） |
| 复盘 | 统计各模式出现频次，频次最高的那一条优先做成自动守卫 |
