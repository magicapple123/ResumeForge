# 界面与交互质量规范

本规范用于维护现有 React + Ant Design 应用。设计以清晰、稳定、可恢复为目标，沿用现有品牌色与业务流程。
适用范围包括首页、岗位、简历、投递、网申、进度、面试、助手、设置及「我的空间」全部页面。

## 模块边界

| 模块 | 职责 | 规模目标 |
| --- | --- | --- |
| `frontend/src/theme/tokens.ts` / `design-tokens.css` | 语义色、间距与层级的 TS / CSS 出口 | 各少于 150 行 |
| `frontend/src/theme/appTheme.ts` | 组装 Ant Design 主题 | 少于 100 行 |
| `frontend/src/styles/foundation.css` | 焦点、通用状态与可滚动容器 | 少于 250 行 |
| `frontend/src/styles/accessibility.css` | 对比度与卡片键盘焦点 | 少于 150 行 |
| `frontend/src/styles/mobile.css` | 手机页头、表单和操作栏适配 | 少于 250 行 |
| `components/navigation/MobileNavigation.tsx` | 手机抽屉菜单与宽屏恢复 | 少于 100 行 |
| `components/navigation/RouteAccessibility.tsx` | 跳过导航、页面播报、标签标题 | 少于 100 行 |
| `components/common/*State.tsx` | 空态、错误和重试反馈 | 单个少于 100 行 |
| `utils/formKeyboard.ts` | 编辑器内的保存快捷键 | 少于 50 行 |

依赖从页面／应用装配层指向共享组件、Hook 和令牌；共享层不依赖页面。
列表请求优先复用 `useApi` 的取消与版本守卫。分组、分页修正和业务校验留在各自领域。
本轮不扩充原有巨型样式文件；后续对 `App.tsx` 的结构治理应单独拆为路由注册、预热 Hook 和布局组件，保持行为不变并逐步验证。

## 视觉基线

- 间距使用 4 / 8px 刻度：行内微间距 4 / 8px，区域间距 16 / 24px。无需为满足刻度重写业务表格与导出模板。
- 控件圆角 8px，面板 16px；常规桌面控件高度 40px，手机主要按钮、单选下拉和图标按钮触控区域至少 48px。
- 品牌主色、成功、警告、错误各有语义令牌；状态必须同时有文字或图标，不能只靠颜色区分。
- 成功／警告沿用 Ant Design 原有的绿色／黄色主题基础色及浅色背景；深色的可读文字色只用于文字，不能作为主题基础色重新生成整套配色。
- 常规文本对比度按 4.5:1 验证，标题与正文的字号、字重、留白形成层级。
- 过渡时长 150–200ms，只用于菜单、状态和反馈；系统开启减少动态效果时缩短动画和滚动过渡。
- 弹层层级沿用已有 `layer` 契约，避免主题调整盖住投投或编辑器。

## 响应式与键盘

375px 手机、768px 平板、1200px 桌面均需实际浏览器验收。
手机使用抽屉导航，页头显示当前位置与数据集，筛选纵向全宽排列，操作组自动换行。
平板保持已有紧凑侧栏，桌面保持完整侧栏。

宽表格、分类条和代码内容在自己的容器中滚动。不能把整页设置为隐藏溢出后就宣布适配通过：
必须同时检查正文的 `scrollWidth`、控件边界、键盘可达性与实际截图。

首个 Tab 入口可跳到正文。菜单、对话框和详情卡片可通过键盘操作，焦点清晰可见。
可点击卡片用独立原生按钮承接键盘，行操作为同级控件，禁止把交互控件嵌在 `role="button"` 中。
输入法合成中的 Enter、正文换行和浏览器／编辑器原有撤销不应被保存快捷键抢占。

## 状态与恢复

| 状态 | 预期行为 |
| --- | --- |
| 加载 | 骨架或加载块保留区域高度，并提供可读的加载提示 |
| 空数据 | 仅在读取成功后显示，区分「还没创建」与「筛选无结果」 |
| 失败 | 持续显示原因与重试入口；保留筛选与已填内容 |
| 成功 | 更新当前列表与必要统计，已有成功提示保持可感知 |
| 保存中 | 按钮反馈忙碌，阻止重复提交；失败时保留编辑内容 |

资料箱／知识库的保存快捷键仅在编辑表单内生效：Ctrl / ⌘ + S 或 Enter。
知识标题在失焦／提交时校验，报错定位到字段，修正后清除错误。
删除、退出和不可逆操作继续使用现有确认流程。

## 验证

先运行相关 Vitest，再运行格式、ESLint、TypeScript、生产构建和全量覆盖率。
浏览器用 `tests/smoke/ui-quality.spec.ts` 检查全部路由在三档宽度的正文边界，并扫描核心页面。
截图必须来自隔离的虚构数据集；自动扫描不等于 WCAG 认证，还需检查焦点顺序、弹窗关闭与真实交互。
现有 Ant Design 表格测量行的已知误报沿用 `a11y.spec.ts` 的明确边界，不能扩大豁免范围。

规范依据：W3C WCAG 2.1 的 Reflow、Bypass Blocks、Focus Visible 与 Contrast Minimum；
表单字段关联和校验沿用当前 Ant Design Form API。
