# "改了没用"排查树

> 症状：代码明明改了，界面/接口/导出结果却和之前一样。
> 结论先给：**九成不是代码问题，而是"你看到的不是新代码"或"你验的不是那条路径"。**
> 按下面的顺序走，每一步都能"排除"或"确诊"，不要跳步。

## 0. 判定链（固定顺序，别倒着走）

```text
① 服务进程是不是新的
   ↓ 是
② 静态产物是不是新的（且服务读的就是它）
   ↓ 是
③ 浏览器/客户端拿到的入口是不是新的
   ↓ 是
④ 请求有没有走到你改的那条路径
   ↓ 是
⑤ 才是代码逻辑问题
```

前四步任意一步为"否"，后面所有现象都无效——包括截图、接口返回、性能数字。

> 只想按症状对照？直接跳 §8 的速查表；本节讲的是顺序与判据。

---

## 1. 进程：改完没重启，或旧进程还占着端口

| 检查 | 判据 |
|---|---|
| 监听者是谁 | 端口对应的 PID，及其**启动时间**是否晚于最后一次改动 |
| 有几个实例 | 同端口只能有一个监听者；开发服务器常见"起了两个、代理指向旧的那个" |
| 新进程是否静默退出 | 端口仍通、但进程不是新的 → 新进程启动失败，旧进程继续服务 |

**高风险操作**：用 `pkill -f "<命令片段>"` 停进程。在 Windows 上，进程名往往不是你以为的那个（例如 Python 服务的真实进程名是 `python.exe`），`pkill` 会"成功返回"但什么也没杀，新进程因端口被占而静默退出。

正确做法：

```powershell
# Windows：按命令行匹配，再按 Id 结束
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*<端口或模块名>*' } |
  ForEach-Object { Stop-Process -Id $_.ProcessId -Force }

# 复查无残留
Get-CimInstance Win32_Process |
  Where-Object { $_.CommandLine -like '*<端口或模块名>*' } |
  Select-Object ProcessId, CreationDate, CommandLine
```

```bash
# macOS / Linux
lsof -nP -iTCP:<port> -sTCP:LISTEN
ps -o pid,lstart,command -p <pid>
```

**判据**：进程启动时间晚于改动时间；且端口上只有一个监听者。

## 2. 产物：包没重建，或重建到了别处

| 检查 | 判据 |
|---|---|
| 产物目录的修改时间 | 是否晚于源码改动 |
| 产物内容 | 用本次新增的**唯一字符串**去产物里 grep，能搜到才算新 |
| 服务读的是哪个目录 | 用 HTTP 取入口文件，与磁盘同名文件比 `sha256` |
| 新旧体积 | 体积完全相同不代表没变，可能只是等长替换；用 `cmp -l` 数差异字节 |

常见陷阱：

- **产物目录通常不进版本库**，所以"工作区干净"完全不能证明包是新的。
- 构建工具在清理输出目录时可能被安全策略拦下而退出，**日志看起来像构建失败，其实模块都编译好了**；换一个仓库外的输出目录即可。
- 服务启动脚本会复制/挂载产物；只重建不重启，或只重启不重建，都会看到旧界面。

```bash
# POSIX（macOS / Linux / Windows 的 Git Bash、WSL）
# 磁盘产物 vs 服务返回的同一文件
sha256sum <dist>/assets/index-*.js
curl -s http://<host>:<port>/assets/index-<hash>.js | sha256sum

# 新旧包差异字节数
cmp -l <old>/assets/index-*.js <new>/assets/index-*.js | wc -l
```

```powershell
# Windows PowerShell 原生等价写法
Get-FileHash <dist>\assets\index-*.js -Algorithm SHA256
Invoke-WebRequest "http://<host>:<port>/assets/index-<hash>.js" | Select-Object -ExpandProperty Content |
  Set-Content -Path $env:TEMP\served.js -NoNewline
Get-FileHash $env:TEMP\served.js -Algorithm SHA256

# 新旧包差异字节数：两边长度相同不代表没变，逐字节比对
$old = [IO.File]::ReadAllBytes("<old>\assets\index-x.js")
$new = [IO.File]::ReadAllBytes("<new>\assets\index-y.js")
Compare-Object $old $new | Measure-Object | Select-Object -ExpandProperty Count
```

> 先确认自己用的是哪一种 shell：PowerShell 里没有 `sha256sum`/`cmp`，直接照抄 bash 段会得到"命令不存在"，很容易被误读成"产物没生成"。

## 3. 网络：地址族、代理与端口

| 现象 | 原因 | 处理 |
|---|---|---|
| `localhost` 通、`127.0.0.1` 连接被拒 | 开发服务器只绑了 IPv6 回环（`::1`） | 用 `localhost`，或显式 `--host 127.0.0.1` |
| 页面能开、接口全 502 | 前端代理指向的后端端口与实际不一致 | 打印实际代理目标，核对端口 |
| 一个请求打到前端自身源、拿到 HTML 404 | 请求封装没有统一补 API 前缀 | 对新增调用点断言"方法 + 完整路径 + 关键请求头" |
| 换端口后仍连旧服务 | 旧的开发服务器实例没停 | 回到第 1 步 |

---

## 4. 请求：有没有走到你改的那条路径

- 打开网络面板/抓包，确认**请求真的发出**、路径与参数符合预期。
- 有些路径不经过统一封装（直连、SSE、原生 `fetch`、表单提交），不会自动补头/补前缀——这类调用点最容易"改了没生效"。
- 用注入方式（拦截并改写响应）验证渲染分支时，要意识到**验的已经不是产品**；注入只能证明"分支可达"，不能证明"用户能到这里"。

**判据**：抓到请求体里包含你新增的字段/值。抓不到，就不是渲染问题。

---

## 5. 解释器与依赖：跑的不是你以为的那套环境

| 现象 | 原因 | 判据 |
|---|---|---|
| 启动即退出、日志只有一两行 | 用了系统解释器，缺项目依赖 | 用项目虚拟环境里的可执行文件；日志里看 import 报错 |
| 改了依赖版本但行为不变 | 依赖装在另一个环境/另一份 site-packages | `python -c "import x; print(x.__file__)"` |
| 类型检查/测试通过但运行报错 | 检查用的解释器与运行用的不是同一个 | 显式把解释器传给检查工具 |

---

## 6. 缓存：三层，逐层排除

| 层 | 表现 | 排除方法 |
|---|---|---|
| 浏览器 | 强刷才生效 | 硬刷新/无痕窗口；确认入口文件 hash 变了 |
| 服务端页面缓存 | 内容变了但模板没变 | 看响应头与缓存键；确认键里含内容签名 |
| 数据/渲染缓存 | 首次生效，第二次回退 | 改一个字节再试；确认缓存键含新字段 |

**缓存键要用语义等价的键**：以全文哈希为键，会让"改一个字"整份重算；改用"会影响结果的最小特征"——例如实体 id + 内容签名 + 数据域，或排序去重后的字符集合——才既稳定又能命中。

---

## 7. 数据层：迁移没跑，或写到了另一个库

- 新增字段后行为不变：确认迁移已执行、且服务连的是那个库文件。
- 本地有多个数据集/多个数据库副本时，确认当前实例指向哪一个（连接串/环境变量/启动参数）。
- 用"写入后读回"验证：写一个可识别的值，再从同一个入口读出来。

---

## 8. 一页速查

| 症状 | 最可能原因 | 第一动作 |
|---|---|---|
| 页面完全没变化 | 旧进程 / 未重建产物 | 查 PID 启动时间；grep 新字符串 |
| 接口 404 但路由写了 | 前缀没补 / 注册顺序被通配路由吞掉 | 抓完整路径；看路由注册顺序 |
| 只有某个页面不对 | 该页读的是另一份数据/另一个接口 | 打开网络面板比路径 |
| 本机好、别人不好 | 环境差异（解释器/时区/滚动条宽度/字体） | 让对方贴版本与截图，别用"我这儿好的"结案 |
| 改一次好、再改又回去 | 缓存键缺字段 / 有第二个写入者 | 找所有写入点；确认键含内容签名 |
| 测试全绿但真机失败 | 桩环境无布局/无网络 | 真实浏览器量 `rect`；抓真实请求 |

---

## 9. 报告这类问题时，请附上

1. 进程启动时间与端口监听者；
2. 产物入口文件名 + 磁盘与服务两份 `sha256`；
3. 抓到的请求（路径、方法、关键头、请求体）；
4. 你改的文件与"应该出现的新字符串"。

有这四项，"改了没用"通常能在五分钟内定位；没有这四项，双方只能互相猜。
