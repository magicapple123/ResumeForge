# Code of Conduct

## Our pledge

To keep collaboration open, friendly and constructive, project participants are expected to respect contributors with different backgrounds, experience and viewpoints, and to keep discussions centered on facts and code.

## Expected behavior

- Use polite, inclusive and professional language.
- Discuss problems, implementations and evidence; never target people.
- Accept well-intentioned change suggestions, and admit uncertainty when it applies.
- Respect other people's time, privacy and work.
- Remove API keys and personal data before sharing logs, screenshots or samples publicly.

## Unacceptable behavior

- Harassment, discrimination, threats, personal attacks or sustained hostile pestering.
- Publishing someone else's private information, or exposing API keys, real resumes and photos.
- Deliberately submitting malicious code, supply-chain attacks or misleading security reports.
- Any other behavior that is clearly unprofessional or unsafe in an open-source collaboration setting.

## Scope and enforcement

This code applies to the project repository, issues, pull requests and discussions, as well as any public setting where you are representing the project. Report behavior problems through the private contact details published in the maintainer's GitHub profile. Report security vulnerabilities strictly as described in [SECURITY.md](SECURITY.md), and never disclose exploitable details in a public issue.

**Reports are handled confidentially.** Maintainers will acknowledge receipt within a reasonable time and explain the outcome of the handling. Depending on the facts, they may issue a reminder, restrict participation or remove inappropriate content. When security is involved, protecting user data and reducing exploitability take priority.
